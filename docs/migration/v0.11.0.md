# Migrating from v0.10.0 to v0.11.0

This release renames a large part of the toolbox's surface. The names are
better, but nothing forwards from the old ones: code written against v0.10.0
will not run until it is updated. There is one exception, noted at the end.

Every substitution below was checked against the released code rather than
taken from a commit message.

## Why the names changed

The internals had drifted. The word "schema" was used for both a schema file
and an openMINDS type; constants lived in several places under several
spellings; base classes sat in a package named after an attribute
(`abstract`) rather than a role; and some names described something the code
did not do. The public surface has also been written down for the first time,
ahead of v1.0.0, which is what made the inconsistencies worth fixing now
rather than after the promise starts binding.

## Classes

| v0.10.0 | v0.11.0 |
|---|---|
| `openminds.abstract.Schema` | `openminds.Node` |
| `openminds.abstract.BaseVisitor` | `openminds.base.Visitor` |
| `openminds.abstract.BaseTransformer` | `openminds.base.Transformer` |
| `openminds.abstract.BaseSerializer` | `openminds.base.Serializer` |
| `openminds.abstract.BaseDeserializer` | `openminds.base.Deserializer` |
| `openminds.abstract.ControlledTerm` | `openminds.base.ControlledTerm` |
| `openminds.base.TypesEnumerationBase` | `openminds.base.TypesEnumeration` |
| `openminds.base.ModulesEnumerationBase` | `openminds.base.ModulesEnumeration` |
| `openminds.internal.abstract.MixedTypeSet` | `openminds.base.MixedTypeSet` |
| `openminds.internal.meta.Type` | `openminds.introspection.MetaType` |

`openminds.abstract` and `openminds.internal.abstract` no longer exist.

## Methods

| v0.10.0 | v0.11.0 |
|---|---|
| `getUnresolvedLinks` | `getUnresolvedLinkIdentifiers` |
| `processInstances` | `buildDocuments` |
| `postProcessInstances` | `postProcessDocuments` |
| `getSemanticIRI` | `getTypeIRI` on a node, `getPropertyIRI` on a mixed-type set |
| `Types.getSchemaName()` | `Types.getTypeName()` |
| `LinkResolverRegistry.instance()` | `LinkResolverRegistry.getSingleton()` |

If you subclass `openminds.base.Serializer`, note that `postProcessDocuments`
is both a rename and the hook you override; a subclass still overriding
`postProcessInstances` will compile and silently never be called.

## Removed with no direct replacement

- `openminds.utility.isEmbeddedType`. It took a type and a property and
  answered a question about the property. Use
  `openminds.introspection.fromClassName(typeName).isPropertyWithEmbeddedType(propertyName)`.
- `openminds.abstract.ControlledTermBase`. The controlled-term base is now
  generated per model version alongside the types.
- `openminds.enum.Types.create`. It was a documented alias; use
  `createInstance`.

## What you may not need to change

`openminds.internal.*` names are not listed here unless they moved somewhere
public. They are implementation details and were never covered by a promise.
Several did move — the whole package now lives under `code/+openminds`
instead of `code/internal` — but the package names are unchanged, so code
referencing them keeps working.

## The one shim

`isUnresolved` still works and forwards to `isReference`, warning once per
session. It is the only deprecation shim in the toolbox and it will be
removed in v1.0.0, so treat the warning as a deadline rather than a
suggestion.

## New in this release

Worth knowing about, since some of it exists to replace a reach into the
internals:

- `openminds.introspection` describes what a type looks like: whether a
  property holds one value or many, links to another node, embeds one, or
  accepts several types. Previously this was `openminds.internal.meta`.
- `openminds.interface.LinkResolver.isTypeKnown` answers the question every
  resolver implementation has to answer first, without naming an internal
  class.
- `serialize` now accepts serialization options directly, including a new
  `PropertyFilter` for emitting only named properties. Note that
  `RecursionDepth` and `IncludeIdentifier` were previously accepted and
  silently ignored; they now take effect.
- `Node.isReference` is no longer hidden.
